# Word Documents (Contracts, Addenda, Bills) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fill the owner's Word templates (several contract templates, one addendum template, one bill template) with app data, download the resulting .docx, and save it to Google Drive, both manually and automatically.

**Architecture:**
- **Pure data builders:** `src/docs/placeholders.ts` turns a contract, addendum or bill into the spec §4 data object.
- **Template filling:** `src/docs/render.ts` wraps `docx-templates` (loaded lazily); `src/docs/inspect.ts` lists and checks a template's commands.
- **Storage:** templates live in a new IndexedDB store (DB v3) and in backups.
- **Drive:** the upload code is generalised from "bill PDF" to "any file at a folder path", so contracts, addenda and bill .docx files reuse the queue, the retry handling and the folder cache.

**Tech Stack:** existing app; add `docx-templates` (MIT, runtime), `docx` and `jszip` (dev only: starter generation and test helpers).

**Spec:** `docs/superpowers/specs/2026-09-26-word-documents-design.md` — read §3–§8 before starting.

## Global Constraints

- **Delimiters:** `{` and `}` (`cmdDelimiter: ['{','}']`). Placeholders are exactly the spec §4 names, and values are strings (money `20.952.000`, dates `dd/mm/yyyy`).
- **Missing values** render as `''`, never `undefined`/`null` (`rejectNullish: false`, and builders never emit nullish).
- **Templates:** at most **5 MB**; must start with the ZIP signature `PK` (bytes `0x50 0x4B`). Kinds: `'contract' | 'addendum' | 'bill'`.
- **Defaults:** at most one default contract template. Removing the default makes the first remaining contract template (by upload date) the default.
- **DB version 3** adds the store `templates` (keyPath `id`); stores from v1/v2 are untouched.
- **Backup `schemaVersion` stays 1:** `templates` holds base64 data, and a missing list is `[]`.
- **Drive:**
  - contracts and addenda: `[driveFolderName, 'Hợp đồng', YYYY of signing (the parent's for addenda), safeName(customer.name)]`;
  - bill .docx: the bill PDF folder `[driveFolderName, YYYY of billDate, safeName(customer.name)]`;
  - .docx MIME type `application/vnd.openxmlformats-officedocument.wordprocessingml.document`.
- **File names:**
  - contract `HĐ {number with / → -} – {customer}.docx`;
  - addendum `{PLnn} – HĐ {parent number with / → -}.docx`;
  - bill `{bill number}_{customer}[_DRAFT].docx`;
  - all cleaned like `pdfFileName`.
- **Auto-upload** needs `driveAutoUpload`, `driveConfigured(settings)`, a template of that kind, and a non-draft record. A missing template skips silently.
- **Warning copy:** `Only upload templates you created or trust — templates can contain small formulas that run in this app.`
- Existing tests keep passing and `npm run build` stays clean. `docx-templates` must not be in the main `index-*.js` chunk.

## Review Focus

1. **A placeholder that Word has split across several formatting runs** (common after editing or spell-check, e.g. `{so_` + `hop_dong}`) must still be filled. Pinned in Task 3 (`fills a placeholder split across runs`).
2. **Customer names containing `&`, `<`, `>` or Vietnamese characters** must appear literally and must not corrupt the .docx. Pinned in Task 3 (`escapes special characters`).
3. **Multi-line detail notes** (`chi_tiet`) must become real line breaks in Word, not one run-on line. Pinned in Task 3 (`turns new lines into Word line breaks`).
4. **A JPEG logo** (Settings accepts PNG and JPEG) must embed with the right extension, and a missing logo must give no image and no error. Pinned in Task 3 (`embeds a JPEG logo; no logo, no image`).
5. **Removing the default contract template** while others exist must leave exactly one default. Contracts that pointed at the removed template fall back to the default. Pinned in Task 1 (`removing the default promotes the oldest remaining`).
